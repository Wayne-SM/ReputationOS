<objective>
Implement clean provider interfaces and zero-cost default local/No-Op implementations for AI Insights, WhatsApp Messaging, Stripe Billing, and Transactional Email, managed by a centralized factory container.
</objective>

<tasks>
1. **Environment Configuration**: Extend `server/src/lib/env.ts` with optional provider configuration keys: `AI_PROVIDER`, `MESSAGING_PROVIDER`, `BILLING_PROVIDER`, `EMAIL_PROVIDER`.
2. **Provider Types & Interfaces**: Define comprehensive domain interfaces in `server/src/providers/types.ts` (`IAiProvider`, `IMessagingProvider`, `IBillingProvider`, `IEmailProvider`, and associated DTOs).
3. **No-Op AI Provider**: Implement `server/src/providers/ai/noop.ai.ts` fulfilling `IAiProvider` at ₹0 cost.
4. **Console Messaging Provider**: Implement `server/src/providers/messaging/console.messaging.ts` fulfilling `IMessagingProvider` by formatting and console-logging review invites at ₹0 cost.
5. **Free-Tier Billing Provider**: Implement `server/src/providers/billing/freetier.billing.ts` fulfilling `IBillingProvider` by granting active access without Stripe dependencies at ₹0 cost.
6. **Console Email Provider**: Implement `server/src/providers/email/console.email.ts` fulfilling `IEmailProvider` by logging transactional notices and alert emails at ₹0 cost.
7. **Provider Factory & Registry**: Implement `server/src/providers/index.ts` exporting `getProviders()`, `setProvider()`, and default initializers driven by environment variables.
8. **Automated Unit Tests**: Create `server/src/providers/__tests__/providers.test.ts` testing default provider outputs, error handling, provider swapping, and factory resolution.
9. **Verification**: Execute `npm test` and `npm run build` in `server` to guarantee full test coverage and clean compilation.
</tasks>
